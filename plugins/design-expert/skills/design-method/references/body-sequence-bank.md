# Body Sequence Bank

`macrostructure-bank.md` covers the first screen. This file covers everything after it — the
part `register/brand.md` names as the proven failure mode: "The failure mode is the
**body**." A hero treatment does not address it; nor does a canon skeleton minus one section.

Ten sequences, one per page in `../../design-web/references/refs-design/` (headings name
the source folder under it), read off shipped code: section order, the principle deciding
that order, what the page does NOT carry from the canon, what subject it suits. Numeric
limits are not restated — `../../design-web/references/layout-discipline.md` owns them and
applies on top of any sequence; colour and type stay in the source sheets.

## Two rules before you pick

**1. A sequence transposes by its principle, never by its list of sections.** Dropping
`edit → annotate → reference → …` onto another product does not give you reve, it gives an
empty imitation; what transposes is "one usage verb per full screen, panel side
alternating". Same test as `../../design-web/references/refs-design/README.md`: if the
sequence could sit on a brand in an unrelated sector unchanged, you copied a composition.

**2. The canon is not the enemy; uniform treatment of it is.** `fora` follows the canonical
order almost to the letter and still does not read generic; its sheet says why, on evidence:
two vertical rules cross every section boundary, so the page is one continuous sheet instead
of a stack of bands; exactly two gradients exist in the whole document and they mark the
opening and the closing and nothing else; vertical padding is set section by section
(160/180/180/160/180/180/180), not one value everywhere; the hero's app window returns at
the end cropped by the section edge. Choosing the canon is legitimate **when it is treated**
— entry 5 exists so it can be chosen honestly instead of by omission.

## The ten sequences

### 1. Mega-Menu Mirror — `harness-recode/design-system.md`

- **Order** — hero (logo marquee inside it) → four anchored domain modules, each h2 +
  intro + scene + tab row (6/4/3/2 tabs) → giant-number band + integrations plate →
  one-slide customer carousel → closing ask = an eight-field demo form → footer.
- **Principle** — the body is the nav's mega-menu unrolled: the four modules are the four
  columns of the Product panel, same order, same links as tabs. Order is by product domain,
  never by buyer stage.
- **Absent from canon** — no pricing (the nav entry points at the CTA), no FAQ, no feature
  card grid (features are the tab panels), no testimonial grid, no paired CTA buttons.
- **Right when** — the offer really is several product domains and the nav already names
  them. Narrow: it needs a genuine taxonomy, not three features dressed up as four.

### 2. Ramp and Newsroom — `cursor-recode/design-system.md`

- **Order** — hero → logo garden → four alternating full-width feature blocks → six-card
  quote wall → trio → changelog rail → team card → highlights rail → title-only closing
  CTA → footer.
- **Principle** — the body climbs an autonomy ramp (you ask, it writes → it runs alone →
  it lives in your other tools → it works with no ask at all), then hands over to dated
  evidence: everything after the quote wall is recency, not argument.
- **Absent from canon** — no pricing, no FAQ, no numbered how-it-works, no metrics band,
  no comparison table, and no form or input anywhere: zero email capture, zero lead gate.
- **Right when** — the product has a real progression of capability AND a public dated
  release rhythm. Without the second half the newsroom tail is filler.

### 3. Numbered Surface Index — `linear-recode/design-system.md`

- **Order** — hero, carrying no button at all → statement block → 1.0 Intake → 2.0 Plan →
  3.0 Build → 4.0 Diffs → 5.0 Monitor → changelog → quotes → pre-footer CTA → footer.
- **Principle** — the numbered sections follow the product's own workflow, and a section
  earns its number only by having a distinct application surface to show. Sub-link counts
  stay irregular (4, 4, 5, none, 3) because content sets them, not the grid.
- **Absent from canon** — no pricing (survives as a nav link), no FAQ, and no hero CTA:
  both asks live in the sticky header and the pre-footer.
- **Right when** — the product has a genuinely ordered workflow and each stage can be
  rendered. It fails on contact if the stages are labels with no surface behind them.

### 4. Verb Reel — `reve-recode/design-system.md`

- **Order** — sticky hero + drifting card strip → 1 Edit → 2 Annotate → 3 Reference →
  4 Templates → 5 Effects → 6 Layers → 7 Reframe → composer (a working input) → gallery
  strip → footer.
- **Principle** — one usage verb per full screen, panel alternating left and right, with
  the two non-mirrored formats placed at positions 3 and 4 so the mirror rhythm never runs
  more than twice unbroken.
- **Absent from canon** — no feature grid (each capability takes a whole screen), no
  testimonials, pricing, FAQ, logo wall, metrics or closing CTA band: the page ends on an
  input field, handing the tool over rather than pitching it.
- **Right when** — the product is a direct-manipulation tool whose verbs each demonstrate
  in one frame. On anything you cannot show operating it becomes seven empty panels.

### 5. Bookended Canon — `fora-recode/design-system.md`

- **Order** — hero (the app window, flat and centred) → intro prose → features, four tabs
  driving one gallery → what-you-get card stack → pricing → FAQ → blog index → CTA, the
  same app window bled off the right edge → footer.
- **Principle** — one object shown twice, and between the two showings each section widens
  the same claim by one degree: the window, the sentence about it, four views of it, three
  of its screens, its price, its objections, its writing.
- **Absent from canon** — testimonials in every form: no quote, no face, no logo wall, no
  metric band. Added outside it: the intro prose, the card stack, the blog after the FAQ.
- **Right when** — you have one object worth showing twice and you will actually treat the
  canon (rule 2 above). Picked untreated, this is the generic page.

### 6. Solo–Duet Cadence, Store Pivot — `umbrel-recode/design-system.md`

- **Order** — hero (solo) → product band, full-bleed photo (solo) → hardware against OS,
  two columns each with a nested 2x2 spec grid (duet) → single wide card band (solo) →
  superpowers snap rail (duet) → store pivot: glow, grid lines, collage, two opposed
  marquees → support cards, 349/211/349, fourth cell a newsletter (duet) → footer.
- **Principle** — alternate one object at full width against two parallel tracks that never
  merge; order by what you can buy first and how far it reaches — the machine, the OS on
  it, one app, what the apps allow, the store they come from, the people around it.
- **Absent from canon** — testimonials, pricing section, FAQ, closing CTA band. Pricing
  dissolves into the product bands as one bare line each; the last support card does the
  CTA's job. No feature grid: each spec tile is a render carrying its own engraved title.
- **Right when** — the offer has a real nesting to walk outward through. Weak on a single
  undifferentiated product, where the duets have nothing to run in parallel.

### 7. Void-Metered Stack — `supercommon-recode/design-system.md`

- **Order** — utility bar → title band (kicker, h1 and hero in one container) → manifesto,
  one paragraph, no visual → duo image with two words on it → two-modes band with a looping
  video → notch band, segmented control → capabilities, ten flat entries → 3x3 pictogram
  grid → exit, one wide button → footer.
- **Principle** — each band states exactly one thing, and the void in front of it is sized
  to what it states: the two longest silences announce the manifesto and the feature grid,
  the two blocks the page most wants read.
- **Absent from canon** — no nav at all (two utility links and a wordmark, no menu, no
  burger at any width), no testimonials, no pricing table (the price is inline on one
  button), no FAQ, no CTA band. Features appear twice, neither time as a card grid.
- **Right when** — one product, one price, and copy short enough that silence reads as
  emphasis. With ordinary marketing prose the voids read as broken spacing.

### 8. Bento Absorption — `xai-recode/design-system.md`

- **Order** — hero holding pill, h1, subtitle, two buttons AND a four-card bento →
  developer duo, text and mini-stats against a code window → numbers banner → news row →
  offerings, two capability panels → footer. Five sections total.
- **Principle** — the canonical feature grid is pulled up *into* the hero instead of
  following it, which is what leaves only five sections; the page shows before it tells, so
  everything after the hero reads as evidence and the only ask is the last thing on it.
- **Absent from canon** — testimonials, pricing, FAQ, logo wall, and any standalone CTA
  band. Added: a numbers banner and a news feed, neither of which the canon has a slot for.
- **Right when** — you can draw the demonstration itself and the argument is credibility
  rather than conversion. Absorbing an empty grid into the hero doubles the emptiness.

### 9. Shrinking Aperture — `mainframe-recode/design-system.md`

- **Order** — non-sticky header that scrolls away for good → hero + a full-window carousel
  of five panels that select nothing → one section holding three blocks (card trio, sticky
  showcase of large frames, attribute duo plus brand rail) → pricing, two plans → closing
  section: a small object, a heading, one button → single-row footer.
- **Principle** — the order is set by decreasing display surface, not by argument, and the
  type never re-amplifies to compensate: the closing heading is smaller than the h1.
- **Absent from canon** — testimonials in any form, FAQ, comparison table, newsletter,
  footer columns, sticky nav, burger. Features exist three times in three different
  geometries, so the page has no single features block.
- **Right when** — the argument is visual and can be staged at genuinely different scales.
  On a text-heavy page there is no aperture to shrink.

### 10. Showreel Canon — `endlesstools-recode/design-system.md`

- **Order** — two-pill sticky bar → opening h1 and a 20-tile mosaic → one demo video →
  eight function tiles → pricing → rail of fourteen review cards → email capture → footer.
- **Principle** — alternate showing output and asking for something, and make every showing
  block a countable set of media (20 tiles, 1 video, 8 tiles, 2 cards, 14 cards) so rhythm
  comes from the count in each set, never from the length of prose.
- **Absent from canon** — FAQ dropped; testimonials and pricing swapped, so the price is
  asked before the proof; a demo block inserted between hero and features; the closing CTA
  is an email capture, not the primary action. Also gone: logo wall, metric row, comparison
  table, footer columns.
- **Right when** — you own enough real output to fill every showing block. It is the canon
  reordered, so it earns nothing if the sets are stock imagery.

## Selection rule

Name the sequence in the plan, next to the hero treatment from `macrostructure-bank.md`:
**"Body sequence: {name} — principle applied here: {one line}."** State the principle in
the brief's own terms, not the source's; a plan naming the sequence but not what its
principle becomes for this subject has copied a composition. Deviating is expected — say
which section moved and why. Sections kept from the canon are still governed by
`register/brand.md` §2 (Body != SaaS Furniture) and its per-section Competitor Lift Test:
an entry here licenses an order, never a section reached by omission.
